# Between Us Mobile

Для продолжения разработки в Claude Code сначала прочитайте [CLAUDE.md](CLAUDE.md) и
[docs/CLAUDE_HANDOFF.md](docs/CLAUDE_HANDOFF.md). В handoff собраны актуальные локальные пути,
доступы без секретов, состояние IPA/OTA, изолированного сервера и ближайшая очередь работ.

«Между нами» — мобильное пространство для пары: планы и поездки, календарь, памятные события, дневник, настроения, договорённости, разбор сложных эпизодов, общий чат и закрытые обращения будущему ИИ-посреднику. Кодовая база ориентирована на iOS и Android; Антон и Лиза — первая тестовая пара, но модель данных уже многопользовательская.

## Что работает в версии 0.3.0

- регистрация и вход по email и паролю;
- безопасная сессия в iOS Keychain / Android Keystore через Expo SecureStore;
- создание пары и присоединение второго участника по одноразовой ссылке, QR или 12-символьному коду;
- ровно два участника в одной паре и полная изоляция данных разных пар;
- синхронизация планов, дневника, памятных событий, информации о паре, договорённостей, конфликтов, настроений и чата;
- приватные изображения планов и событий с проверкой токена при каждом открытии;
- отдельный персональный фон, который не меняет оформление телефона партнёра;
- «Тихий канал»: исходный текст недоступен партнёру, шифруется AES-256-GCM и сохраняется без API чтения;
- локальный кэш по ключу пользователя и пары, optimistic UI и повторная синхронизация каждые 10 секунд;
- OTA-обновления Expo для совместимого JavaScript-кода.

## Архитектура

```text
src/app/          Expo Router: auth, onboarding, tabs and feature screens
src/components/   shared mobile UI and Liquid Glass surfaces
src/domain/       pair-agnostic domain models
src/services/     API client, SecureStore, sync/cache and image processing
src/state/        auth, pair and shared-data providers
server/           Fastify + PostgreSQL API, migration and deployment files
```

Мобильный клиент обращается к `https://186.246.45.4.nip.io:9444`. API работает отдельной службой на `127.0.0.1:3100`; наружу его публикует отдельный TLS-процесс на порту `9444`. PostgreSQL не открыт в интернет. Существующие VPN, DNS, панели и их порты не используются приложением и не входят в его зависимости.

Схема API и эксплуатационные детали: [server/docs/API.md](server/docs/API.md), [server/docs/openapi.yaml](server/docs/openapi.yaml), [server/docs/OPERATIONS.md](server/docs/OPERATIONS.md).

## Локальная разработка

```powershell
cd D:\between-us-mobile
npm install
$env:EXPO_PUBLIC_API_BASE_URL='https://186.246.45.4.nip.io:9444'
npm run verify
npm start
```

Проверка сервера:

```powershell
cd D:\between-us-mobile\server
npm install
npm run build
npm test
```

Секреты не хранятся в репозитории. `EXPO_PUBLIC_API_BASE_URL` является публичной настройкой, а пароли БД, JWT и ключ шифрования существуют только в защищённом окружении сервера.

## Установка тестовой IPA

Workflow `Build unsigned iOS IPA` создаёт неподписанный `BetweenUs-unsigned.ipa`. На Windows его можно подписать своим Apple ID через Sideloadly. На Mac удобнее использовать Sideloadly, AltStore или локальную сборку Xcode. При бесплатной подписи Apple приложение обычно требуется переподписывать раз в семь дней; OTA обновляет JavaScript, но не заменяет обязательное переподписание и не устанавливает новые нативные зависимости.

## Безопасность и ограничения беты

- Пароли хешируются Argon2id и никогда не сохраняются в клиенте.
- Access token короткоживущий; refresh token ротируется, а повторное использование старого токена отзывает семейство сессий.
- Приглашения хранятся только в виде хеша, имеют срок жизни 24 часа и одно использование.
- Все общие запросы ограничены текущей парой на сервере, а локальный кэш разделён по `userId + pairId`.
- Медиа проверяются по MIME и сигнатуре, ограничены по размеру и доступны только участникам пары.
- Для публичного запуска ещё нужны подтверждение email, восстановление пароля, управление устройствами, удаление аккаунта и пары, резервное копирование, мониторинг и отдельный сервер.

Текущий VPS подходит для закрытой тестовой пары и небольшой альфы. Массовый запуск должен работать на отдельной инфраструктуре; API спроектирован так, чтобы перенос состоял из миграции PostgreSQL и каталога медиа с заменой адреса API.
