# Between Us Mobile

Мобильное приложение «Между нами» для iOS с общей кодовой базой для будущей Android-версии.

## Текущий статус

Первый рабочий инкремент подготовлен:

- Expo SDK 57, React Native 0.86 и React 19.2.3;
- TypeScript в строгом режиме;
- Expo Router и нативная нижняя навигация;
- экраны «Сегодня», «Календарь», «Планы», «Дневник» и «Ещё»;
- общая дизайн-система для iOS и Android;
- доменные модели пары, планов, дневника и календаря;
- адаптер Expo SecureStore для будущей сессии;
- безопасный API-клиент с тайм-аутом и без встроенных секретов;
- демонстрационные локальные данные вместо подключения личного web-vault.
- зависимости установлены и закреплены в `package-lock.json`;
- TypeScript, проверка исходников и все 20 проверок Expo Doctor проходят;
- статическая web-сборка используется как доступный на Windows smoke-тест интерфейса.

Проект создан на Windows, поэтому iOS Simulator и локальная подпись iOS здесь недоступны. Для iOS
используются Expo Go на физическом устройстве, EAS Build либо Mac с Xcode. EAS-профили уже описаны,
но для облачной сборки нужен вход в Expo и затем доступ к Apple Developer account.

## Установка

Требуется Node.js 22.13.x, который соответствует Expo SDK 57.

```powershell
cd D:\between-us-mobile
npm install
npx expo install --fix
npm run verify
npm start
```

Доступная на Windows статическая проверочная сборка:

```powershell
npm run export:web
```

Для iOS на Mac:

```bash
npm run ios
```

Для облачной тестовой сборки iOS:

```powershell
npx eas-cli build --platform ios --profile preview
```

## Безопасность

- Личные ключи и токены не находятся в исходном коде.
- Чувствительная сессия предназначена только для SecureStore / Keychain / Android Keystore.
- Текущие ключи веб-версии не переносятся в мобильный клиент.
- `EXPO_PUBLIC_*` переменные считаются публичными и не должны содержать секреты.
- Перед синхронизацией нужен новый мобильный API с регистрацией, приглашением партнёра, отзывом устройств
  и серверной авторизацией на уровне пространства пары.

## Следующий инкремент

1. Войти в Expo и проверить интерфейс на физическом iPhone через Expo Go.
2. Реализовать экран первого запуска и создание локального защищённого профиля.
3. Спроектировать мобильный API и схему миграции данных без копирования старых личных ключей.
4. Добавить полноценные формы планов, дневника и памятных событий.
5. Подготовить закрытую EAS-сборку и распространить её через TestFlight.
6. После стабилизации — Android-проверка той же кодовой базы.
