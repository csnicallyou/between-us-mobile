# Architecture

## Решение

Приложение строится на Expo SDK 56 и React Native 0.85. Expo Router обеспечивает файловую навигацию,
а TypeScript — единые контракты для iOS и Android.

### Почему Expo

- одна кодовая база для iOS и Android;
- EAS Build позволяет получать iOS-сборки без локального Xcode;
- SecureStore использует Keychain на iOS и Keystore на Android;
- Continuous Native Generation позволяет добавлять нативные настройки без постоянного хранения папок
  `ios/` и `android/` в репозитории;
- приложение можно постепенно расширять нативными модулями.

## Слои

### Presentation

`src/app` содержит только маршруты и композицию экранов. Переиспользуемые элементы находятся в
`src/components`, дизайн-токены — в `src/theme`.

### Domain

`src/domain` не импортирует React Native. Здесь находятся идентификаторы участников, планы, дневник,
настроения и календарные элементы. Это позволит использовать те же типы в синхронизации и тестах.

### State

`AuthContext` управляет безопасной сессией, `PairContext` — текущей парой и приглашениями,
`AppDataContext` — общим снимком и синхронизацией. Локальный кэш разделён по пользователю и паре;
сервер остаётся источником истины. Полноценная очередь офлайн-операций и разрешение конфликтов ещё не реализованы.

### Services

`secureStorage.ts` хранит сессию в Keychain/Keystore. `backendClient.ts` задаёт сетевой контракт,
тайм-аут и нормализованные ошибки, а `syncRepository.ts` преобразует серверные записи в доменные модели.
Адрес API передаётся через `EXPO_PUBLIC_API_BASE_URL`; секреты там
хранить нельзя.

## Будущая синхронизация

```text
UI -> use cases -> local encrypted database -> sync queue -> mobile API
                                                   |
                                                   +-> conflict resolver
```

Мобильное приложение не использует текущий зашифрованный JSON веб-версии напрямую. Fastify API уже
поддерживает пользователей, пары, версии записей, настроения, чат, закрытые обращения и защищённые вложения.
Следующие инфраструктурные слои — подтверждение email, устройства, восстановление, полноценный журнал
операций, офлайн-очередь и дальнейшее обобщение пары до нескольких пространств отношений.

## Платформенные границы

- Общая бизнес-логика остаётся в TypeScript.
- Различия iOS/Android концентрируются в адаптерах и дизайн-токенах.
- Биометрия, виджеты, push-уведомления и защита экрана реализуются через платформенные сервисы.
- Любая функция сначала проверяется на iOS, затем проходит Android-проверку до объединения в стабильный релиз.
