Статус на 2026-08-13: выработана стилистика (Liquid Glass, светлая тема) и

**В код `src/app` ничего не внесено** — вся работа лежит в

навигационная перекладка.

Читать в связке с `docs/CLAUDE_HANDOFF.md` (машина/релиз/сервер) и
`docs/ROADMAP.md` (очередь разработки) — этот файл только про визуал.

## Как посмотреть макеты

Файлы в `docs/redesign/mockups/*.html` — самодостаточные HTML-страницы,
390×~900px (макет iPhone). Открываются прямо в браузере с диска, без
сервера. **Лучшая точность — в Chrome/Chromium**: материал использует
`backdrop-filter` с прозрачностью и лёгкой карточной геометрией; Safari и
Firefox рендерят похоже, но без части нюансов.

Чтобы получить PNG (например, для показа кому-то, кто не откроет HTML):

```bash
npm install --no-save playwright   # локально, не коммитить в package.json
npx playwright install chromium
cd docs/redesign/mockups
node render.js today.html today.png
node render.js calendar.html calendar.png
node render.js entries.html entries.png s-all      # или s-plans / s-journal
node render.js we.html we.png
node render.js inner.html agreements.png v1        # v1..v4, см. ниже
node render.js settings.html settings.png
node render-ai.js                                 # все состояния пространства ИИ
node render-auth.js                               # все 13 экранов входа и онбординга
```

## Ключевые решения по стилистике

- **Гарнитура — Golos Text** (`GolosText.ttf` в этой папке; лицензия SIL
  Open Font License 1.1, текст лицензии — `GolosText-OFL.txt`, файл взят из
  `google/fonts` репозитория, директория `ofl/`, редистрибуция разрешена).
  Другие гарнитуры на выбор — Manrope, Onest, Nunito Sans — были показаны и
  отклонены.
- **Материал — светлое почти прозрачное стекло**, откалиброванное под
  нативный `GlassView` (`expo-glass-effect`, уже в зависимостях проекта,
  уже обёрнут в `src/components/NativeGlassLayer.tsx`). Тёмная тема
  проверялась для сравнения и **не выбрана** как основная.
- **Чернила** — одна база `rgba(33,30,41, …)` в трёх уровнях прозрачности
  (94% / 60% / 40%), больше ступеней не вводить.
- **Якорь композиции** — графитовый градиент (`#3B3644 → #26222E`) для
  единственного основного действия на экране. Цвет в остальном зарезервирован
  только для точек настроения и статусных меток — не для украшения.
- **Иерархия — глубиной, не цветом**: активное состояние (вкладка, сегмент)
  отличается плотностью стекла, а не заливкой.
- **Правило Apple, которого мы держимся**: стекло живёт только на слое
  управления (панели, шапки, карточки-контейнеры). Списки, фото и текст
  внутри карточек на стекло не переводить — иначе всё превращается в кашу.
  Из-за этого правила, например, ячейки календаря — обычная полупрозрачная
  заливка на одной стеклянной карточке, а не 42 отдельных стекла.
- **Тени и блики привязаны к размеру объекта**, не фиксированы: маленький
  элемент отбрасывает короткую тень, крупный — длинную. Формулы — в
  `light.css` и `glass.js`, раздел «геометрия тени».

### Важное техническое предупреждение

`glass.js` в этой папке эмулирует часть эффекта (лёгкое размытие,
насыщенность фона, тон, тень с цветом, вычисленным из фона под объектом)
средствами браузерного CSS/Canvas. **Это техника для превью в браузере,
не код для переноса в приложение.** В React Native нет `backdrop-filter` и
canvas-сэмплинга фона. При реализации:

- Используется нативный `GlassView` (`expo-glass-effect`) — он сам считает
  преломление, дисперсию и адаптивные тени лучше любой эмуляции.
- Переносится **геометрия и решения**: радиусы, отступы, три уровня
  чернил, графитовый якорь, «стекло только на слое управления», структура
  теней (близкая/дальняя, короче на маленьких элементах).
- Не переносится: сам механизм `feDisplacementMap`/канальной дисперсии
  из `glass.js` — это заведомо тупиковый путь для RN.
- На Android и iOS младше 26 `GlassView` недоступен — нужен запасной
  вариант через `expo-blur` (уже в зависимостях) с той же геометрией, но
  без преломления. Компонент `NativeGlassLayer.tsx` уже возвращает `null`
  не на iOS — на его месте и появится запасной путь.

## Навигационная структура (финальная)

Нижняя панель, пять слотов, центральный — не вкладка, а стеклянная сфера
с анимацией нейронов, ведущая в пространство ИИ:

```
Сегодня   Календарь   ◉ (сфера ИИ)   Записи   Мы
```

Изменения относительно текущего кода (`src/app/(tabs)/_layout.tsx`,
5 вкладок: index/calendar/plans/journal/more):

- **Планы + Дневник → «Записи»**, одна вкладка с фильтром
  «Всё / Планы / Дневник». Модели данных не меняются, идёт только слияние
  на уровне навигации и ленты.
- **«Ещё» → «Мы»**, урезано с 11 пунктов до 4: Наша история, Важное о нас,
  Договорённости, Разбор ссор. Это подраздел про отношения на текущей
  вкладке `(tabs)/more.tsx`.
- **Настройки ушли из списка в шапку** (иконка-шестерёнка): аккаунт и пара,
  уведомления, фон и контраст, экспорт данных, диагностика Liquid Glass.
- **Поиск ушёл из списка в шапку** (иконка-лупа), доступен с любой вкладки.
- **Чат втроём и Тихий канал переезжают в центральную сферу** — вместе с
  ещё не спроектированным режимом «Наблюдения ИИ». Обоснование: Тихий
  канал — обращение к будущему ИИ-посреднику, ему не место в общем списке
  разделов «Мы»; а «Разговор втроём» — по словам Антона, вероятно, основная
  функция продукта в будущем (M3), поэтому заслуживает самого доступного
  места в интерфейсе, а не рядового пункта меню.
- Пятая вкладка «Мы» физически — это текущий файл `more.tsx`, только с
  другим набором разделов и другой вёрсткой карточек (бенто вместо плоского
  списка).

## Центральная сфера (ИИ)

`neurons.js` рисует объёмную сеть узлов внутри стеклянного шара: узлы живут
в 3D-объёме, а не на плоскости, шар медленно вращается, ближние узлы ярче и
крупнее дальних. Палитра — чёрно-белая (по последней правке в этой сессии,
было цветное — отклонено). Тело шара — стекло с направленным бликом сверху
слева и отражённым светом снизу справа (это и делает его шаром, а не
кругом с бликом).

Активное состояние сферы в панели — не заливка плашки, как у остальных
вкладок (плашки у сферы нет), а кольцо вокруг неё и более плотный гало.
Размер при этом не меняется: сфера и так самый заметный элемент панели.

## Пространство ИИ (`ai.html`)

Единственное место в приложении с **тёмной темой** — это разделяет его с
остальным светлым интерфейсом физически, а не только по названию. Материал
тот же по геометрии, но тень и кромка заданы вручную: на чёрном фоне тень,
сэмплированная из фона (обычная формула `glass.js`), сама становится почти
чёрной и объём пропадает.

Три режима переключаются сегментером, где **«Разговор» — центральный и
главный**: он крупнее соседей, залит светлым якорем и приподнят. Обоснование
то же, что и для самой сферы — по словам Антона это вероятная основная
функция продукта.

| Режим | Что переносит из кода | Состояния в макете |
|---|---|---|
| Разговор | `src/app/chat.tsx` | короткая лента; пустое состояние «Начните общий разговор» (в коде — строка `styles.empty`); заполненный чат в работе — группировка подряд идущих сообщений одного автора, разделители дней, набранный текст в поле ввода |
| Тихий канал | `src/app/quiet.tsx` | пустая форма; отправка — поля заблокированы, кнопка недоступна, подпись «Шифруем и отправляем…» (в коде — `disabled={sending}`) |
| Наблюдения | новый раздел | только пустая заглушка до подключения модели |

Кнопка «i» в шапке ведёт на экран **«Что видит ИИ»** — прямое отображение
ограничений из `CLAUDE.md`: что доступно модели (общий чат, записи, планы,
календарь, договорённости, разборы ссор), что закрыто навсегда (исходный
текст Тихого канала — его не видит партнёр, и ИИ его не показывает и не
пересказывает; ничего за пределами пары), и путь любого изменения:
предпросмотр → подтверждение → журнал → отмена. Этот экран не украшение:
он единственное место, где правила приватности сформулированы для
пользователя, а не только для разработчика.

Состояние `s-full` показывает чат **после** подключения модели: сообщение
ИИ в нём предлагает добавить событие и обещает показать карточку до
сохранения. Это иллюстрация правила «предпросмотр → подтверждение», а не
описание сегодняшнего поведения — сейчас ИИ не подключён, и в остальных
состояниях об этом прямо написано в плашке над лентой. Группировка
сообщений (аватар и имя не повторяются у подряд идущих сообщений одного
автора, время — только у последнего в группе) в текущем `chat.tsx` не
реализована и появится вместе с новой вёрсткой ленты.

## Вход и онбординг (`auth.html`)

Единственная часть приложения без нижней панели: карточка стоит по центру
экрана, как и сейчас в `AuthScaffold` (`justifyContent: "center"`).

Знак — два полупрозрачных круга внахлёст: пересечение плотнее, потому что
заливка удваивается. Это буквально «между нами» — общее у двоих. Знак
намеренно **не** стеклянный: на 46 px размытие даёт ту самую тёмную кромку,
с которой мы боролись, а удвоение заливки и так читается. Тот же приём
работает второй раз на экране «оба на месте», где круги — аватары А и Л.

Внутри стеклянной карточки поля, ячейки кода и вторичные кнопки —
**обычная полупрозрачная заливка, не стекло**. Это то же правило Apple:
карточка и есть слой управления, класть стекло на стекло нельзя. Первый
вариант макета был сделан неправильно (стекло в стекле) и переделан.

Все 13 состояний сняты с существующего кода, ничего не придумано:

| Состояние | Откуда |
|---|---|
| `s-signin` `s-signup` `s-forgot` `s-sent` `s-reset` `s-done` | `(auth)/sign-in`, `sign-up`, `forgot-password`, `reset-password` |
| `s-verify` | `EmailVerificationPanel` — 6-значный код, «Код уже отправлен» на кулдауне |
| `s-choose` `s-create` `s-invite` `s-join` `s-ready` `s-load` | ветки `PairSetupScreen` в `(onboarding)/index.tsx` |

Что добавлено сверх текущего кода и требует одобрения:

- **Индикатор шага онбординга** (три точки внизу) — сейчас его нет, шаг
  пользователю ничем не обозначен.
- **Ячейки кода вместо одного поля** — в коде это один `TextInput` с
  `maxLength={6}`. Разбивка на шесть ячеек это только вёрстка, но её надо
  делать так, чтобы вставка кода из письма целиком продолжала работать.
- **Дата отношений уже заполнена** (`14 февраля 2021 г.`) — в коде
  по умолчанию подставляется сегодняшняя дата. Это не изменение
  поведения, просто в макете правдоподобное значение.

QR на экране приглашения — псевдокод (`qr.js`), нужен только для фактуры.
Настоящий рисует `react-native-qrcode-svg` из ссылки приглашения, как
сейчас в `PairInviteCard`.

## Открытые вопросы, требующие решения Антона

1. **«14 карточек» в «Важное о нас»** (`we.html`, плитка раздела) —
   выдумано для макета, потому что при импорте этот раздел был пуст.
   Реальное число нужно взять из фактических данных пары перед реализацией.
2. **Редактирование эпизода в «Разборе ссор»** — в текущем коде
   (`src/app/conflicts.tsx`) есть только создание и удаление долгим нажатием,
   редактирования нет. Макет (`inner.html`, `v2`) нарисован так, будто
   карточка открывается по тапу — это подразумевает новую функцию
   (редактирование), которую надо явно одобрить перед реализацией.
3. **Долгое нажатие для удаления** — есть во всех четырёх разделах «Мы»,
   нигде не обозначено визуально ни в старом, ни в новом дизайне. Стоит
   заменить на свайп или пункт меню карточки — иначе действие невозможно
   обнаружить.
4. **Число режимов в пространстве ИИ** — в макете три, где «Наблюдения ИИ»
   до M3 остаются пустой заглушкой («Ожидается на следующем этапе»).
   Альтернатива — два режима до появления модели, чтобы не показывать
   заведомо пустой раздел. Решение не принято.
5. **Автоматические годовщины отношений** («полгода вместе» и т.п.) не
   появляются в календаре — это вычисляемая дата, а не запись, и модель
   `Memory` их не хранит. Если нужно — это отдельная небольшая фича, не
   часть текущего редизайна.

## Сборка IPA — процесс без изменений

Эта сессия не трогала нативный код и зависимости, поэтому существующий
процесс сборки не менялся. Это не новая инструкция, а сверенное описание
того, что уже работает (`.github/workflows/ios-unsigned.yml`,
`docs/CLAUDE_HANDOFF.md`):

1. **Триггер**: пуш в `master`, затрагивающий `app.json`, `package.json`,
   `package-lock.json`, `src/**` или сам workflow-файл — либо ручной запуск
   («Build unsigned iOS IPA» → Run workflow) в GitHub Actions.
2. **Раннер** — `macos-26` в GitHub Actions. Шаги: `npm ci` →
   `npm run typecheck && npm run check:source && npx expo-doctor` →
   `npx expo prebuild --platform ios --clean` → `xcodebuild` с отключённой
   подписью (`CODE_SIGNING_ALLOWED=NO`) → упаковка `.app` в
   `BetweenUs-unsigned.ipa` + `.sha256`.
3. **Результат** — артефакт `BetweenUs-unsigned-ios` в запуске workflow,
   хранится 7 дней.
4. **Установка на телефон** — скачать артефакт, установить через
   Sideloadly или AltStore на телефон с бесплатной Apple ID подписью.
   Подпись обычно истекает через 7 дней с момента установки и требует
   переустановки.
5. **Важно**: `runtimeVersion.policy` в `app.json` уже стоит `fingerprint`
   (не `appVersion`) — это специально сделано в прошлой сессии, чтобы
   изменения нативных зависимостей не улетали через OTA на бинарник, в
   котором их нет. Не менять эту политику обратно.
6. **Известное и не связанное с редизайном ограничение**: iOS-виджет
   подтверждённо не работает на бесплатной подписи (Sideloadly ломает
